## Browser scenarios

Each scenario ran at desktop 1440 × 1000, tablet landscape 1194 × 834, tablet portrait 834 × 1194 and mobile 390 × 844. The same 24 checks ran on the development server and the compiled Vite build.

1. Overview, category and text search, required modifier, special instruction, add/remove/quantity totals, expandable portrait cart and horizontal overflow checks.
2. Dine-in final confirmation, add-on round, separate kitchen batches, prepare/ready/serve, insufficient-tender blocking, cash settlement, receipt and DIRTY → CLEANING → AVAILABLE.
3. Takeaway packaging, pay-before-kitchen sequencing, demo QR provider and manual confirmation, resulting kitchen ticket.
4. Occupied-order reopening, early-payment acknowledgment, exact three-way split of RM 29.60 into RM 9.86 / 9.86 / 9.88, zero remaining balance and table retained while kitchen work is active.
5. All operational navigation, responsive overflow checks, report generation and search-ready report table. Desktop also downloads mock PDF and Excel files.
6. Refresh resets local mock changes; the trailing-slash preview route works; original POS storage sentinels remain intact.

Unit coverage also exercises invalid/unknown modifiers, note trimming, quantity limits, immutable submitted lines, partial takeaway payments and draft-discard blocking, overpayment, duplicate settlement blocking, item allocation/mixed-payment limits, equal-split cents, table movement/reservation, shift gating/reasons and report date filtering.
